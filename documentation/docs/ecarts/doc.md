# Écarts assumés — tickets DOC

Chaque ticket DOC livré laisse ici son tableau d'écarts — ce que le dépôt fait autrement que la
carte, et pourquoi. La règle du registre est sur [la page d'index](./index.md).

## Écarts assumés avec le ticket DOC-01

| Écart                                                                 | Raison                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `"type": "module"` absent du `package.json` du site                   | Tous les autres workspaces le déclarent ; ici il **casse le build**. Le bundle serveur de Docusaurus est du CommonJS : chargé comme module ES, il sort sur `require.resolveWeak is not a function`. Vérifié dans les deux sens, et le gabarit officiel de Docusaurus ne le déclare pas non plus.                                                                   |
| Documentation servie à la racine du site, `blog: false`               | Le ticket demande un site de documentation technique, ni blog ni vitrine. Une page d'accueil marketing serait un fichier de plus à tenir pour un lecteur qui cherche une réponse, et un segment `/docs/` de plus dans chaque URL.                                                                                                                                  |
| `@repo/typescript-config/base.json` plutôt que `@docusaurus/tsconfig` | Le tsconfig de Docusaurus pose `baseUrl`, que TypeScript 6 déclare déprécié (TS5101) ; son gabarit s'en tire avec `ignoreDeprecations: "6.0"`, ce que `packages/ui` a déjà refusé de faire. Ses quatre réglages utiles sont recopiés dans le tsconfig du site, avec le renvoi qui va bien.                                                                         |
| `@docusaurus/plugin-content-docs` en dépendance de développement      | `sidebars.ts` importe son type `SidebarsConfig`. Le gabarit officiel ne la déclare pas — npm aplatit son arbre et la rend visible quand même. Le `node_modules` strict de pnpm, lui, n'expose que ce qu'un package déclare.                                                                                                                                        |
| `@easyops-cn/docusaurus-search-local` retenu                          | Le ticket demande un plugin hors ligne sans en nommer un. C'est le seul encore maintenu : `docusaurus-lunr-search` n'a pas publié depuis janvier 2025, et `@cmfcmf/docusaurus-search-local` est l'original dont celui-ci est la réécriture. Sa fonctionnalité « Ask AI » reste éteinte — le paquet qui la porte est une peer **optionnelle**, que rien n'installe. |
| Recherche indisponible sous `pnpm dev`                                | Limite du plugin, pas un réglage : l'index n'est produit qu'au build. Le critère se vérifie donc sur un `build` suivi d'un `start`, et la page d'accueil du site le dit à son lecteur.                                                                                                                                                                             |
| `documentation/i18n/fr/code.json` ajouté                              | Le plugin de recherche ne livre que les traductions `en`, `de`, `vi` et `zh-CN` : sans ce fichier, une interface par ailleurs française afficherait « Search ». Seules ses dix chaînes y figurent — recopier les 92 clés qu'écrit `docusaurus write-translations` figerait dans le dépôt des traductions que `@docusaurus/theme-translations` tient déjà à jour.   |
| Job `build` déclenché aussi par les pull requests                     | Le critère ne parle que de la publication depuis `main`. Sans ce garde-fou, un renvoi mort ou un diagramme invalide ne se verrait qu'après le merge, sur le site en ligne. Le chevauchement avec QA-02 est borné à `documentation/**`.                                                                                                                             |
| `actions/configure-pages` avec `enablement: true`                     | GitHub Pages n'était pas activé sur le dépôt, et le ticket veut une publication « opérationnelle ». Un clic dans les réglages ne se versionne pas, ne se relit pas et ne se rejoue pas ailleurs.                                                                                                                                                                   |
| `documentation/tsconfig.json` ajouté au résolveur d'imports d'ESLint  | Hors du périmètre littéral du ticket, dans `packages/config-eslint`. Sans lui, `import-x/no-unresolved` n'a aucun projet TypeScript à opposer aux fichiers du site.                                                                                                                                                                                                |
| `core-js` refusé dans `allowBuilds`                                   | Dépendance transitive de Docusaurus, dont pnpm 11 bloque le script d'installation et attend un arbitrage. Son `postinstall` ne compile rien : il affiche une bannière Open Collective, et rien d'autre — vérifié dans son `postinstall.js`.                                                                                                                        |
| Barre latérale plate, six documents                                   | Six catégories d'une seule page afficheraient des sections qui ne se déplient pas. Chaque entrée devient une `category` le jour où DOC-02 lui ajoute une deuxième page ; la forme est écrite en commentaire dans `sidebars.ts`.                                                                                                                                    |
| Ni service Compose, ni variable `.env`, ni cible `make`               | Le ticket s'arrête au workspace pnpm. Le port 3004 est donc porté par le script `dev` du site, là où les services conteneurisés tiennent le leur d'une variable `*_HOST_PORT`.                                                                                                                                                                                     |
| Ni favicon, ni logo, ni feuille de style propre                       | Aucun habillage n'est demandé. Le thème par défaut suffit à lire, et `src/css/custom.css` viendra le jour où il y aura quelque chose à y écrire.                                                                                                                                                                                                                   |
| Le site alourdit l'étage `deps` des images de frontend                | `docker/frontend/Dockerfile` installe tout le monorepo. Conséquence anticipée par le `.dockerignore` d'INFRA-05a, qui garde les sources du site dans le contexte de build pour cette raison exacte ; restreindre l'installation relèverait de ce ticket-là. L'étage a été reconstruit avec le site en place, il passe.                                             |

## Écarts assumés avec le ticket DOC-02a

| Écart                                                                                                                         | Raison                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cinq pages plutôt qu'une, et la section devient une `category`                                                                | La portée nomme un dossier, pas un nombre de pages. Une page unique aurait mêlé le vocabulaire, la règle, la liste des interdits et la carte — quatre genres qu'on ne consulte pas au même moment. La transformation en catégorie était par ailleurs **prescrite nommément** par le commentaire de `sidebars.ts`, qui citait DOC-02a.                                                                                                                                                                                                                                      |
| Une page de **glossaire**, que le ticket ne demande pas                                                                       | L'objectif écrit du ticket est qu'un développeur ou un agent produise du code conforme « sans deviner les conventions ». Or les autres pages emploient _agrégat_, _port_, _tenance_, _affectation_ sans les définir, et le sens de chacun est décidé par un ADR. Sans cette page, le guide suppose acquis exactement ce que le ticket veut cesser de supposer.                                                                                                                                                                                                             |
| La carte porte **deux** diagrammes, pas un                                                                                    | Aucun module n'en importe un autre aujourd'hui — vérifié module par module, et prouvé en continu par le contrat 3. Mêler les flux réels et les flux prévus sur un seul schéma laisserait un lecteur pressé lire un graphe connecté là où il n'y en a pas. Le premier montre l'état, le second les intentions, en pointillés et datées par leur ticket.                                                                                                                                                                                                                     |
| Le croisement `scheduling` × `organization` **absent** du diagramme des flux prévus                                           | Ce n'est pas un flux : l'[ADR-0026](../adr/0026-fiche-technique-praticien.md) décide que le croisement ne peut vivre dans aucun des deux modules et appartient au point de composition. Le dessiner comme une flèche entre eux inverserait le sens de la décision. Il est énoncé en prose, comme contre-exemple.                                                                                                                                                                                                                                                           |
| Cinq modules sur la carte, quand l'[ADR-0003](../adr/0003-monolithe-modulaire.md) en décide six                               | `profile` (BACK-32) est décidé mais n'existe pas dans `src/app/modules/`. Il figure sur le diagramme comme **à naître**, sans surface publique : l'omettre contredirait l'ADR, le dessiner comme les autres ferait croire à du code qui n'est pas là.                                                                                                                                                                                                                                                                                                                      |
| Un module d'exemple écrit, éprouvé, puis retiré                                                                               | Le guide promet un exemple **complet**, pas des fragments. Un module `demo` de treize fichiers a donc été déposé dans `src/app/modules/`, passé aux cinq contrats, à Ruff et à Mypy — tous verts —, puis supprimé. Ce que la page montre est du code qui compile et qui est conforme, pas une illustration approximative.                                                                                                                                                                                                                                                  |
| Les sept sorties d'erreur de la section dépannage sont **reproduites**, pas reconstituées                                     | Chaque contrat a été cassé pour de bon, sa sortie copiée, puis le code remis en état. C'est la méthode de BACK-04b, qui avait joué sept violations réelles pour la même raison : un message d'erreur recopié de mémoire envoie chercher au mauvais endroit.                                                                                                                                                                                                                                                                                                                |
| Premiers **Tabs**, premier **`sequenceDiagram`**, premier **surlignage de lignes**, premiers séparateurs `---` du dépôt       | Quatre capacités que le site portait sans les avoir jamais servies. Les Tabs montrent un port et ses deux adaptateurs côte à côte, ce qu'aucun texte ne remplace ; le `sequenceDiagram` est la seule forme qui rende un cycle de vie lisible ; le surlignage désigne la ligne qui porte la règle dans un fichier entier. Les `---` rompent avec le corpus, qui sépare par des `##` : ils ne servent que sur la page guide, la seule assez longue pour que les `##` seuls ne respirent plus.                                                                                |
| Les Tabs engagent le fichier guide sur le format **MDX**                                                                      | `ecrire-un-module-conforme.md` est le seul `.md` du dépôt à porter des `import … from '@theme/…'`. Cela fonctionne parce que `markdown.format` n'est pas déclaré et que son défaut en Docusaurus 3 vaut `'mdx'`. Le jour où quelqu'un passe à `format: 'detect'` — geste courant avant une v4 — la page afficherait ses deux lignes d'import en toutes lettres, **sans casser le build**. Le renommer en `.mdx` aurait fait de lui le seul fichier de son espèce ; la dépendance est donc consignée ici plutôt que déguisée.                                               |
| Les phrases normatives de [Architecture du service](../backend/architecture-du-service.md) remplacées par des renvois         | Cette page portait déjà, au mot près, le sens des dépendances, les trois anti-patrons, l'argument du mapping manuel et la règle d'indépendance. Les recopier aurait produit deux textes à tenir d'accord. C'est le geste de DOC-02b, qui avait sorti des README « une soixantaine de lignes de justification » pour les renvoyer aux ADR. Deux tableaux restent en double — la règle des 3 modèles et celle des espaces — parce qu'ils énoncent ici la **règle** et là-bas l'**état des lieux** : la revue contradictoire les a relevés, et l'arbitrage est de les garder. |
| Onze fichiers touchés hors de `documentation/docs/architecture/`                                                              | Quatre pages promettaient ce contenu **au futur** et devenaient fausses à la livraison ; le registre des écarts et sa page d'index sont exigés par la règle du registre ; `sidebars.ts` était prescrit par son propre commentaire. Le reste est détaillé aux trois lignes suivantes.                                                                                                                                                                                                                                                                                       |
| Trois affirmations corrigées dans [Qualité et typage](../backend/qualite-et-typage.md), une dans `backend/api/pyproject.toml` | Le critère « relu contre BACK-04 et BACK-04b » les a mises au jour. Le contrat 1 « nomme douze paquets » (écrit deux fois) alors qu'il en nomme **seize** ; il « couvrira les suivants le jour où ceux-ci naîtront » alors que `scheduling` et `notifications` sont nés. Et le `pyproject.toml` portait la même erreur — « les sept autres », pour onze. Corriger la page en laissant la source fausse aurait été pire que ne rien faire ; les deux disent désormais la règle **sans compter**, pour ne plus périmer.                                                      |
| Une affirmation corrigée dans `.github/workflows/documentation.yml`                                                           | Le commentaire promettait qu'« un renvoi mort **ou un diagramme invalide** fait echouer la CI ». C'est faux pour Mermaid : le thème le rend côté **client**, dans une `ErrorBoundary` — vérifié dans le paquet installé. Le ticket qui livre quatre diagrammes est le bon endroit pour lever ce faux sentiment de sécurité, et pour dire que la relecture visuelle est le seul filet.                                                                                                                                                                                      |
| Une précision apportée à la docstring de `shared/domain/ports/__init__.py`                                                    | Elle énonçait « un port est une `ABC` aux methodes asynchrones ». La page normative allait la reprendre telle quelle, alors que `FileStorage.generate_presigned_url` et `TokenService.audience_for` sont **synchrones à dessein**, chacune avec son motif écrit. Une règle publiée contre le code n'aurait pas survécu à sa première lecture.                                                                                                                                                                                                                              |
| Le guide « Architecture Hexagonale & DDD » n'existe pas dans le dépôt                                                         | Le ticket demande de le « reprendre ». Aucune copie n'en est versionnée, et le dépôt a déjà consigné un écart **avec** lui (les entités sont un fichier plat, pas un dossier — arbitrage de BACK-04). Les règles reprises ici sont donc celles que le dépôt a retenues, et les deux entorses vivantes sont nommées sur la page des interdits plutôt que passées sous silence.                                                                                                                                                                                              |
| Quatre items de la checklist non cochés                                                                                       | « Les premiers ADR sont rédigés », `CONTRIBUTING.md`, le fichier d'instructions pour agents et la recette de bout en bout sont des **reliquats d'avant le découpage** de DOC-02 : ils relèvent de DOC-02b, livré, et de DOC-02c. Les cocher ici les ferait disparaître du reste à faire.                                                                                                                                                                                                                                                                                   |

## Écarts assumés avec le ticket DOC-02b

| Écart                                                                | Raison                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `numberPrefixParser: false` ajouté à `docusaurus.config.ts`          | Hors de la portée littérale, qui s'arrête à `documentation/docs/adr/`. Par défaut Docusaurus **retire** le préfixe numérique d'un nom de fichier (`0001-monorepo.md` → id `monorepo`) : il le lit comme un artifice de tri. Pour un ADR, ce numéro est l'identité de la décision — sans ce réglage, « ADR-0001 » ne serait citable ni en URL ni dans un lien.  |
| Numérotation chronologique, pas l'ordre de la carte                  | La carte liste le monolithe en premier ; le registre numérote dans l'ordre des tickets fondateurs (SETUP-01 → BACK-15). Les ADR se référencent entre eux — la tenance s'appuie sur le monolithe modulaire, l'appartenance datée sur la tenance — et un renvoi qui pointe toujours vers un numéro **inférieur** se lit sans aller-retour.                       |
| Gabarit enrichi d'un tableau de tête et d'une section « Références » | Les cinq sections demandées y sont. Le statut devient un tableau — statut, date de consignation, tickets — pour que le critère « chaque ADR renvoie aux tickets qui l'appliquent » ait une place fixe et vérifiable d'un coup d'œil ; « Références » pointe les fichiers du dépôt qui portent la décision, au lieu d'en paraphraser le contenu qui périmerait. |

## Écarts assumés avec le ticket DOC-02d

| Écart                                                                         | Raison                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| La page documente un harnais que **BACK-12 reprendra**                        | L'alternative était d'attendre ce ticket. Mais le manque bloque aujourd'hui — la relecture de la PR #60 conclut « je livrerais sans tests » —, et une page qui annonce elle-même sa date de péremption vaut mieux qu'une absence. Le tableau « Ce que BACK-12 changera » est l'endroit où cette dette est écrite, plutôt que laissée à découvrir.                                                                                                                  |
| **Aucun décompte de tests** n'est écrit, alors que le constat en cite un      | Le dépôt a déjà tranché contre les nombres en commentaire — le contrat 1 d'Import Linter et son commentaire de `pyproject.toml` ont été réécrits « sans compter » par DOC-02a, précisément parce qu'un décompte périme au premier ajout. La page donne à la place la commande qui compte, et le lecteur obtient un chiffre juste plutôt qu'un chiffre daté.                                                                                                        |
| Les résultats attendus sont **dérivés du code**, non recopiés d'une exécution | La suite n'est pas rejouable sur l'environnement de rédaction : `[tool.uv] required-version` exige uv ≥ 0.12.5, et la pile PostgreSQL / Redis / MinIO n'y tourne pas. Chaque « Attendu » est donc énoncé **sans nombre ni sortie littérale**. Les messages cités, eux, sont copiés du code qui les émet — c'est la règle que DOC-02a avait posée en sens inverse pour ses sorties d'erreur : un message reconstitué de mémoire envoie chercher au mauvais endroit. |
| Deux défauts du jeu de marqueurs sont **nommés**, pas seulement décrits       | Le ticket demande de documenter les marqueurs. Or `-m otp` ne joue pas les tests d'OTP sur doublure, et `--strict-markers` n'est pas activé : présenter la liste sans le dire aurait produit une page fausse, à laquelle un lecteur se serait fié pour juger d'une couverture. Le correctif appartient à BACK-12, qui livre le jeu complet ; la page se borne à ne pas mentir.                                                                                     |
| Une note ajoutée à [Doublures en mémoire](../backend/doublures-en-memoire.md) | Hors de la portée déclarée. Cette page **suppose acquis** l'écriture d'un test sur doublure — c'est le reproche exact de la relecture. La livrer sans le renvoi laisserait le lecteur au même endroit qu'avant.                                                                                                                                                                                                                                                    |
| Cette page cesse d'**énumérer ses tickets** en tête                           | L'en-tête nommait « DOC-01, DOC-02a et DOC-02b », liste à rallonger à chaque livraison et déjà fausse une fois écrite celle-ci. Elle adopte la forme de `back.md`, qui ne nomme personne. Même geste que le décompte ci-dessus, et même motif.                                                                                                                                                                                                                     |
