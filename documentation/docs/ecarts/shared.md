# Écarts assumés — tickets SHARED

Chaque ticket SHARED livré laisse ici son tableau d'écarts — ce que le dépôt fait autrement que la
carte, et pourquoi. La règle du registre est sur [la page d'index](./index.md).

## Écarts assumés avec le ticket SHARED-01

| Écart                                                             | Raison                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Critère « les 3 applications affichent un composant » non vérifié | `frontend/*` ne contient encore que des `.gitkeep` : FRONT-01 à FRONT-03 restent à faire. Le contrat qu'elles devront honorer est décrit sur la page [La bibliothèque @repo/ui](../frontend/bibliotheque-ui.md), et ce qui était vérifiable ici l'a été — typage, lint, et compilation réelle du thème. |
| `sonner` à la place du composant `toast`                          | Le registre shadcn n'expose plus de `toast` pour la base `radix` ; `sonner` est son composant de notification. `toast` n'existe que pour la base Base UI.                                                                                                                                               |
| `field` à la place du composant `form`                            | L'entrée `form` du registre est devenue un stub sans fichier. L'ancien `form.tsx` était soudé à react-hook-form, que FRONT-05 remplace par TanStack Form. `field` fournit les mêmes primitives — label, description, message d'erreur — sans imposer de bibliothèque.                                   |
| `ThemeProvider` ajouté au périmètre                               | Le ticket ne demandait que les variables. Sans le fournisseur qui pose la classe `.dark`, chaque application recâblerait next-themes de son côté et les trois finiraient par diverger — l'inverse de l'objectif du package.                                                                             |
| Accent `emerald` écrit à la main dans `globals.css`               | La CLI shadcn sait poser une couleur de base, pas une couleur d'accent : seul le générateur web `ui.shadcn.com/create` le fait. Les valeurs employées restent celles du registre au caractère près, ce que confirme `shadcn info`.                                                                      |
| Pas de preset Tailwind partagé                                    | Tailwind v4 n'a plus de fichier de configuration JavaScript : le thème **est** `globals.css`, et le `content` d'autrefois s'écrit `@source`. SHARED-02 devra en tenir compte pour `packages/config-tailwind`.                                                                                           |
| `@tailwindcss/cli` en dépendance de développement                 | Ni le ticket ni le build ne le réclament, mais c'est le seul moyen de prouver que le thème compile tant qu'aucune application n'existe.                                                                                                                                                                 |
| `shadcn` et `tw-animate-css` en `dependencies`                    | Le registre les place en `devDependencies`. Ce sont des `@import` de `globals.css`, donc nécessaires au **build des applications** : en devDependencies, un `pnpm install --prod` en image Docker (INFRA-05) casserait la compilation CSS.                                                              |

## Écarts assumés avec le ticket SHARED-02

| Écart                                                              | Raison                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `@repo/typescript-config` et `@repo/tailwind-config`               | Le ticket écrivait `@repo/config-typescript`. Les deux packages du même genre déjà en place s'appellent `@repo/eslint-config` et `@repo/prettier-config` : une seule convention de nommage vaut mieux que la fidélité littérale. Les dossiers, eux, sont ceux du ticket. |
| Pas de preset Tailwind au sens de la v3                            | Tailwind v4 n'a plus de configuration JavaScript. Le preset est `theme.css`, un fichier importé — le mécanisme que Tailwind documente lui-même pour partager un thème entre projets.                                                                                     |
| `content: ['../../packages/ui/src/**']` → `@source '../ui/src/**'` | Même directive, syntaxe v4, et surtout autre point d'origine : `@source` est résolu relativement à la feuille de style qui le porte, ici `packages/config-tailwind/theme.css`.                                                                                           |
| `postcss.config.mjs` déplacé hors de `packages/ui`                 | Revient sur un choix de SHARED-01. La chaîne PostCSS est de l'outillage Tailwind : la laisser ailleurs que le thème obligeait les applications à connaître deux packages pour une seule préoccupation. Aucune n'existant encore, rien à casser.                          |
| `components.json` pointe sur `theme.css`, hors du package          | Sans cela, `shadcn add` écrirait ses variables de thème dans le `globals.css` de `@repo/ui` et le thème se remettrait à diverger. `shadcn info` continue de répondre `vega` / `mist` / `emerald`, ce qui le vérifie.                                                     |
| Variables de typographie ajoutées au périmètre                     | Le ticket demande que le preset porte « la typographie ». Il ne peut pas porter la police elle-même — c'est `next/font`, donc l'application. Le preset porte donc le contrat : `--font-sans` lit `--font-juui-sans`, avec repli.                                         |
| Dépendances Tailwind en `dependencies`                             | `tailwindcss`, `@tailwindcss/postcss`, `tw-animate-css` et `shadcn` sont nécessaires au **build** des applications. En `devDependencies`, un `pnpm install --prod` en image Docker (INFRA-05) casserait la compilation CSS — même raisonnement qu'en SHARED-01.          |
| Critère « une modification du preset se répercute sur les 3 apps » | `frontend/*` ne contient encore que des `.gitkeep`. Ce qui était vérifiable l'a été : changer `--primary` dans le preset change bien le CSS compilé de `@repo/ui`, atteint par le même lien symbolique que celui qu'emprunteront les applications.                       |
| `nextjs.json` livré sans consommateur                              | FRONT-01 à FRONT-03 en dépendent ; le poser maintenant est précisément ce qui garantit que les trois applications démarreront identiques.                                                                                                                                |

## Écarts assumés avec le ticket SHARED-03

| Écart                                                                                              | Raison                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Le schéma vient d'un fichier exporté, pas de l'URL `/openapi.json`                                 | Le ticket écrivait « l'URL `/openapi.json` de l'API (ou un fichier exporté) ». La seconde branche est la seule tenable : la route est fermée en production, la CI n'a aucun serveur à interroger, et FastAPI sert son schéma sur une ligne unique — le diff que le versionnement doit rendre lisible aurait été illisible. La décision est consignée en [ADR-0019](../adr/0019-contrat-openapi-exporte.md).                                                                                                                                                                                                                                                                                                |
| Un ADR de plus, alors que l'ADR-0007 existait déjà                                                 | 0007 décide le générateur, les trois sorties, le mutator et le généré versionné ; il ne dit rien de la provenance du schéma. Or ce choix crée un second artefact versionné, traversant les deux chaînes d'outils, avec sa propre étape obligatoire et sa propre vérification. C'était une décision, pas un détail d'application.                                                                                                                                                                                                                                                                                                                                                                           |
| `fetch` natif plutôt qu'un client HTTP tiers                                                       | Le ticket demande « un mutator personnalisé encapsulant l'instance HTTP » sans nommer de bibliothèque. `fetch` est le défaut d'Orval 8, natif dans Node 24 comme dans les navigateurs cibles, et c'est ce sur quoi Next.js s'appuie pour son cache. Ajouter `axios` aurait mis une dépendance HTTP dans le bundle des trois applications, alors que le dépôt n'en avait aucune.                                                                                                                                                                                                                                                                                                                            |
| Trois fichiers écrits à la main, là où le ticket n'annonçait que `src/mutator.ts`                  | `errors.ts` change avec le format d'erreur du backend, `runtime.ts` avec l'environnement et la convention d'authentification, `mutator.ts` avec le contrat d'appel d'Orval : trois raisons de changer, trois consommateurs. Le découpage sert directement le critère de tree-shaking — importer `ApiError` dans une frontière d'erreur n'entraîne ni `fetch` ni lecture d'environnement.                                                                                                                                                                                                                                                                                                                   |
| Aucun export racine `"."` dans la carte `exports`                                                  | Le critère « exports nommés uniquement, pas de barrel géant » cesse d'être une règle que la revue doit tenir : `import … from '@repo/api-client'` est refusé par le résolveur lui-même. Les sous-chemins suivent un motif (`./api/*`) plutôt qu'une clef par étiquette, faute de quoi chaque nouveau module backend aurait exigé une ligne de `package.json` — la synchronisation manuelle que ce ticket existe pour supprimer.                                                                                                                                                                                                                                                                            |
| `@tanstack/react-query` épinglée en 5.101.4 et non en dernière version                             | 5.102.5 avait été publiée le jour même, et la politique de chaîne d'approvisionnement de pnpm l'a écartée. pnpm proposait une exclusion ; contourner sa propre garde pour gagner une version mineure sans consommateur n'aurait rien acheté.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| La dépendance n'est déclarée que par le package, pas par les trois applications                    | Le code généré l'importe, donc elle est nécessaire au build : `dependencies`, comme les dépendances Tailwind de SHARED-02. Les applications ne la déclarent pas parce qu'elles ne l'importent pas — le `QueryProvider` de FRONT-04 vit dans ce même package. Un seul exemplaire, donc un seul contexte React : c'est la panne que l'on évite, deux copies rendant le fournisseur invisible aux hooks sans la moindre erreur de compilation.                                                                                                                                                                                                                                                                |
| Aucune entrée `paths` pour `@repo/api-client` dans les trois `tsconfig.json`                       | Vérifié plutôt que supposé : avec `moduleResolution: "bundler"`, `tsc` 6.0.3 résout un sous-chemin du package par la **seule** carte `exports`. L'entrée qui existe pour `@repo/ui` double donc cette carte, et son commentaire — « suffit à Next, mais pas à `tsc` » — contredit `base.json`, qui décrit `bundler` comme la résolution qui lit les cartes `exports`. En ajouter une seconde aurait figé un chemin relatif dans trois fichiers de plus, pour rien.                                                                                                                                                                                                                                         |
| Le critère « un hook généré appelle réellement l'API » est prouvé sur la fonction, pas sur le hook | Rendre un hook exige un `QueryClientProvider` (FRONT-04) et un runner de test frontend (QA-02), tous deux hors périmètre. `make verify-api-client` appelle donc les fonctions de requête que les hooks appellent — même chaîne : URL construite par Orval, mutator, réseau, types — contre le vrai backend. Le hook lui-même reste couvert par `pnpm typecheck`. **FRONT-04 a levé la moitié qui lui revenait** : le `QueryClientProvider` existe, et la politique de cache, la fabrique de clés et le routage des 401 sont désormais **exécutés** — hors ligne par `pnpm --filter @repo/api-client test`, et contre la pile par `make verify-api-client`. Rendre le hook lui-même reste suspendu à QA-02. |
| Le montage de `make verify-api-client` compile le package en CommonJS dans un dossier jetable      | Node 24 efface les types à la volée mais reste un résolveur ESM, qui exige des extensions explicites — or Orval écrit ses imports relatifs sans extension. Une passe `tsc` contourne cela sans ajouter la moindre dépendance. Le fichier `tsconfig.verify.json` porte l'unique dérogation du dépôt à `moduleResolution: node10`, et disparaîtra avec QA-02.                                                                                                                                                                                                                                                                                                                                                |
| `scripts/` entre dans le périmètre de Mypy, et le script d'export vit hors de `src/`               | Le contrat `service-spaces` est déclaré `exhaustive` sur le paquet `app` : un `app/cli/` aurait fait échouer `make lint` tant que sa place dans la hiérarchie n'était pas écrite. Un exportateur est de l'outillage, pas un cinquième espace du service. Il reste vérifié par Mypy — c'est le seul code Python du dépôt dont la **sortie** est commitée.                                                                                                                                                                                                                                                                                                                                                   |
| `packages/api-client/openapi.json` exclu de Prettier                                               | Mesuré : la forme canonique de `json.dumps` fait 144 lignes, Prettier la recolle en 125. Les deux se réécriraient indéfiniment et la vérification anti-dérive échouerait selon celui qui a tourné en dernier — la boucle exacte que le fichier documente déjà pour `pnpm-lock.yaml`.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Rien ajouté à `.gitattributes`, et surtout pas `linguist-generated`                                | GitHub replierait alors par défaut le diff du dossier généré, alors que l'ADR-0007 tient précisément cette visibilité pour le bénéfice qui justifie de versionner. Le `* text=auto eol=lf` déjà en place couvre le seul besoin réel : des fins de ligne stables, sans quoi la vérification échouerait selon le poste.                                                                                                                                                                                                                                                                                                                                                                                      |
| Un workflow de CI à part, plutôt qu'un job de `ci-backend.yml`                                     | Les `paths` se déclarent par workflow, jamais par job. L'y greffer aurait relancé les contrats d'architecture sur toute pull request frontend, ce que ce fichier refuse par écrit ; s'en tenir à `backend/**` aurait laissé passer une édition manuelle du dossier généré — le cas que l'ADR-0007 vise en premier.                                                                                                                                                                                                                                                                                                                                                                                         |
| Le commentaire du `scope-enum` réécrit, hors du périmètre littéral                                 | Il annonçait « reste `api-client` en SHARED-03 ». Le laisser intact aurait été une consigne périmée en tête du fichier même qui la rend caduque.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Deux écarts de FRONT-01 et FRONT-02 levés                                                          | Leurs lignes `@repo/api-client` annonçaient leur levée « au ticket qui le crée ». C'est fait, pour les trois applications d'un coup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| L'étiquette `identity` ne produit aucun fichier                                                    | Le routeur du module est déclaré mais ne porte encore aucune route (BACK-28 et suivants) : le tag existe dans le schéma sans opération, et Orval n'a rien à en tirer. Le client se limite donc aujourd'hui à `health` — la tuyauterie est posée, les modules métier la rempliront.                                                                                                                                                                                                                                                                                                                                                                                                                         |
